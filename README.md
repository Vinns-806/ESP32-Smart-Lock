# ESP32-S3 智能门锁（BLE 近场开锁）

基于 ESP32-S3 + ESP-IDF + FreeRTOS 的门锁原型：手机靠近自动开锁，同时支持 4×4 键盘密码开锁，本地用有限状态机管理「锁定 / 开锁 / 惩罚」三态。

> 个人项目 · 独立开发 · 2026.07 – 至今

## 功能

- **BLE 近场开锁**：GAP 广播扫描 + 设备名白名单 + RSSI 双阈值，手机广播 100 ms 时实测 **< 1 s**（GATT 版本可到 0.3 s）
- **密码开锁**：4×4 矩阵键盘输入，支持删除、连续错误 30 s 锁定
- **本地显示**：I2C OLED 显示当前状态与操作提示
- **状态机管理**：锁定 / 开锁 / 惩罚三态，含迁移条件与超时
- **总线自恢复**：I2C 死锁时用 9 个 SCL 时钟 + STOP 恢复，无需整机重启

## 硬件

| 模块 | 型号 | 说明 |
|---|---|---|
| 主控 | ESP32-S3 | ESP-IDF v5.5.5 |
| 显示 | 0.96" OLED | I2C 接口 |

## 软件架构

FreeRTOS 下拆成三个任务，BLE 在 GAP 回调里更新共享状态，状态机只在状态任务里跑：

| 任务 / 回调 | 职责 | 触发方式 |
|---|---|---|
| 键盘任务 | 行列扫描、消抖、密码比对 | 周期扫描 |
| RSSI 滤波任务 | 3 点滑动均值、信号过期清零 | 200 ms 周期 |
| 状态任务 | FSM 状态迁移、超时处理、驱动舵机与 OLED | 100 ms 周期 |
| GAP 回调 | 广播扫描、设备名匹配、更新 RSSI | 事件驱动 |

```
键盘任务 ─┐
          ├─→ 共享状态 + 事件标志 ─→ 状态机（锁定/开锁/惩罚）─→ 舵机 + OLED
BLE 回调  ─┘
```

> 注：任务间用 `volatile` 共享状态 + 标志位通信。已知这不是最优解——更严谨的做法是加事件队列和互斥量，见 TODO。

## 关键实现

### 1. BLE 近场判定

做过两套方案，最终停在 GAP，原因写在下面：

| 方案 | 做法 | 响应 | 代价 |
|---|---|---|---|
| GATT 连接 | 建立连接后按连接事件读 RSSI，3 次采样 | **0.3 s** | 需要配对/连接，手机端要配合，功耗高 |
| GAP 广播 | 被动扫描广播包，按设备名匹配 + RSSI 判定 | **< 1 s**（广播 100 ms）<br>约 3 s（广播 1 s） | 无需连接，但响应被手机广播间隔卡住 |

GAP 的延迟不是代码慢，是采样率被限制死了：

```
延迟 ≈ 手机广播间隔 × 采样次数 ÷ 扫描占空比
```

手机广播间隔 1 s、3 次采样、60% 占空比 → 约 3–5 s，和最初实测一致（1.8–3 s）。把手机端广播间隔调到 100 ms、超时收紧到 800 ms 后，实测 **< 1 s**。

### 2. I2C 总线死锁恢复

现象：OLED/传感器通信卡死，SDA 一直被从机拉低，重启外设也没用。

定位：逻辑分析仪抓 SDA/SCL 波形，确认忙等时 SDA 恒低、SCL 被释放。

解决：手动发 9 个 SCL 时钟，把从机正在输出的字节读完，再发 STOP，然后重新初始化 I2C 外设。

### 3. 键盘扫描

- 行列扫描 + 软件消抖，避免连按一次触发多次；
- 支持删除键与「连续错误 30 s 锁定」，锁定期内忽略输入。

## 遇到的问题

| 现象 | 怎么定位 | 怎么解决 |
|---|---|---|
| 首次匹配就开锁（不管远近） | 串口打印滤波值，发现是 -20 这种离谱数 | 滤波历史初值从 0 改成 -100 |
| 滤波一直卡在 -88 不动 | 读代码发现重置条件用的是输出值 | 改成按原始值判断，并加“信号过期即清空” |
| I2C 总线死锁，整机卡住 | 逻辑分析仪抓 SDA/SCL 波形 | 9 个 SCL + STOP，重新初始化外设 |
| 键盘开锁不亮灯/不转舵机 | 对照两条开锁路径 | 把副作用统一放进 SYS_UNLOCKED 分支 |
| 键盘误触、连击 | 串口打印按键事件 | 加消抖与状态锁 |

## 编译与运行

```bash
# 需要 ESP-IDF v5.5
idf.py set-target esp32s3
idf.py build
idf.py -p COM5 flash monitor
```

烧录前修改 `main/smart_lock_main.c` 顶部的 `TARGET_NAME`（手机蓝牙名）与 `PASSWORD`（开锁密码）。

## 已知问题 / TODO

- GAP 响应依赖手机广播间隔：100 ms 时实测 < 1 s，1 s 时约 3 s；
- 当前白名单仅做设备名识别，**任何人把蓝牙名改成同一个就能开锁**，未实现配对绑定与加密，属于原型阶段；
- 门锁密码硬编码在源码里，量产应存入 NVS 并支持修改；
- 舵机硬件损坏，当前用 OLED 显示与 LED 指示开锁状态，PWM 输出可用逻辑分析仪验证（50 Hz / 0.5–2.5 ms）；
- 任务间共享变量缺少互斥保护，后续会改为事件队列。
